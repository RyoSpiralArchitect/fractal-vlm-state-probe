## Construction And Storage

The constructor assigns uint32 source-index slices and tile payload arrays.
The independent oracle uses explicit successor dictionaries, pixel assignments
and scalar RGB formulas; only the registered RNG specification is shared.
All four maps and all 25 raw arrays/PNGs are audited and sealed before the
first processor call. The raw seal records zero calls started.

The pinned processor-only preparation is unchanged: PIL RGB input,
text=["<image>"], return_tensors="np". Native arrays are copied to contiguous
C-order storage without changing dtype, shape or any native word. Features
are computed from those saved-order words, so memory strides cannot change
float64 reduction order between capture and file replay. No arithmetic
re-normalization, clipping, metadata override or backend substitution.

## Calibration And First Failure

After raw sealing, replay all 128 historical jobs in their recorded order
without computing new real-image features. Only after parity, call the
processor on the 25 synthetic inputs in registered fixture/shift order,
sentinel last. Every call has a prior reserve check; attempted and returned
calls are separate counters. Save each valid-size returned native array and
its complete non-pixel metadata before evaluating its matching gates.

Compute and preserve all fixed diagnostics for an acquired case, including
all twelve signed feature residuals, before raising its first ordered gate
failure. Do not start the next processor call after failure. No retry/resume,
replacement input, changed guard/phase, feature removal or tolerance change.
The sentinel's expected nonmatch remains a passing negative control.

Success requires all 300 oracle vector pairs, 216 matched feature comparisons,
2,340 joint-multiset comparisons, 24 changed-array checks and 12 word-exact
shams, plus historical parity and the two sentinel grid checks. Numerical
acceptance remains maximum absolute error <=1e-10, relative tolerance zero.

An unexpected failure stores the original exception, progress and immutable
file inventory. File-only verification may audit this retained partial run,
but its status is FAILED_CALIBRATION_AUDITED, never PASS. Planned versus
actual counts and the first failure stay explicit; unavailable cases are not
imputed. Failure audits are not a retry or a release to further acquisition.

## Independent File Verification

Two fresh file-only verifications reconstruct maps/raw images through the
explicit oracle, check saved PNG/array words, all captured native arrays,
features and residuals, and reproduce every complete case audit. They never
instantiate a processor or model. Historical parity receipts are joined to
their pinned expectations, not independently regenerated by verification.

Each verifier emits five ledgers, complete actual/oracle feature and signed
residual NPZ archives, and a summary: eight outputs requiring byte-identical
replay. All full raw/native arrays remain local for native-word auditing.
The feature archives alone do not reconstruct the native processor tensors.
Partial failure output contains only actually acquired/computed records;
missing planned quantities are not promoted into matching results.
